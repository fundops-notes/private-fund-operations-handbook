# 设计并评估一次 redo 改善试点

全部工时、测试结果与验收门槛均为教学设定，不是行业统一要求。练习在隔离环境进行，不向真实生产注入错误，不自动批准撤销人工控制。

目标：一份试点章程、一张风险—控制—测试矩阵、一份包含停止条件的评估意见。

准备：了解复核与独立验证的区别；可先阅读redo、委托代理和PDSA单元。不要求编写自动化程序。

建议投入：约120分钟，可分两次完成

## 先理解：效率与控制覆盖要分别证明

重复计算占用大量时间，并不自动说明它没有价值。应先把流程拆成具体控制目的：检查文件齐备、字段口径、价格和参数依据、计算逻辑、输出版本以及异常关闭。然后观察现有redo在哪些目的上有效，哪些地方只是重复了相同输入和算法。

本例的改善假设是：通过文件完整性校验、版本锁定与差异分类，减少整理和机械比对时间，同时保留关键独立证据与异常判断。这个假设包含两项可分别验证的主张——处理时间下降、重要错误仍能被发现。不能用其中一项通过代替另一项。

PDSA强调先作预测，再实施试验、研究结果与调整。本项目采用这一学习逻辑，但测试门槛由教学情景自行设定。正常样本一致只说明正常路径有一定支持，边界、缺失和重复数据需要单独验证。五天观察也不能证明季末、不同资产或新产品全部可用。

## 练习材料：现状、方案与约束

虚构团队每天为一个人民币产品复核外包输出，当前平均投入120人分钟：整理输入30、机械重算45、差异调查30、签署留痕15。目标试点只覆盖该产品的现金与持仓核对，不覆盖新资产估值、费用方法变更或全部NAV发布控制。

候选方案V1自动检查文件清单、记录数与匹配差异，保留人工异常调查和最终批准。独立银行证据仍须取得；不允许以服务商文件同时充当唯一输入和独立核对来源。团队拟减少机械重算，但未获得生产切换批准，现行控制在试点期间继续执行。

本题验收约定：端到端稳态人分钟至少下降30%；八个必测场景中的三类关键失败（缺文件、重复记录、同源错误）不得漏检；不能出现未经批准的发布；原始证据、版本与回退能力可用。任何关键条件不满足，不能建议按现方案推广。阈值只是练习约定，真实项目应按风险与授权制定。

| 需要明确的角色 | 教学职责 |
| --- | --- |
| 流程负责人 | 提出目标、协调资源、提出推广建议 |
| 业务复核人员 | 定义预期结果与独立证据，调查差异 |
| 工具维护人员 | 实现或配置规则，保留版本并修复缺陷 |
| 独立评估角色 | 检查测试覆盖、证据和残余风险 |
| 有权批准人 | 在职责范围内决定试点和生产切换；两者分开 |


请完成：写出试点范围、排除范围、假设、验收条件、角色、停止条件和回退方案。不要只写“提高效率”。

## 第一步：把风险映射为控制与测试

先问如果这类错误真的发生，哪一道控制会发现它，谁会看到提示，系统是否阻止继续处理。随后设计带有预期结果的测试。没有预期结果的运行记录，只能证明执行过程序，不能证明程序处理正确。

测试材料应来自本练习的虚构数据或经批准的隔离样本。缺文件与空文件分别测试，重复记录与更正重发分别测试，正常匹配与同源错误分别测试。关键标识、日期和控制总数应同时纳入，避免仅按金额能对上就结束。

独立证据的取得也是控制链的一部分。如果程序擅长发现格式错误，却在双方输入相同且错误时全部通过，应明确剩余验证由谁完成。可以采用人工独立核验补充，但必须计入工时、权限、证据与验收，不能在方案中把它当作不存在的成本。

| 测试ID | 隔离测试情景 | 预期结果 |
| --- | --- | --- |
| T01 | 正常文件、数量和金额一致 | 允许进入后续复核；记录运行版本 |
| T02 | 应收文件缺失 | 阻止形成完整性通过结论并升级 |
| T03 | 同批次重复一条记录 | 识别重复，不重复计入 |
| T04 | 银行与服务商均被替换为同一错误源 | 独立证据检查应识别替换或阻断依赖 |
| T05 | 文件业务日期错误 | 提示并停止使用错误时点 |
| T06 | 金额相同但账户或币种不同 | 不能错误匹配 |
| T07 | 旧批次之后收到更正文件 | 识别版本与重跑影响，不重复计入 |

## 第二步：阅读V1结果，区分速度与可靠性

V1在T01、T02、T03、T05、T06、T07符合预期；T04未发现同源错误，错误地显示全部通过；T08被误判为必须停止。八个场景中六个符合预期，三类关键失败中的两个被检出。正常情景的速度再快，也不能抵消T04关键漏检。

另有五天平行运行工时，见下表。“候选核心流程”已经包含输入准备、运行、异常调查与签署；“额外独立复核”尚未包含其中，需要加回。其数值是角色投入的人分钟，不是从收件到完成的钟表时间。若以后保留这道复核，它就是稳态成本，不能为了显示节约而从统计中删去。

测量同时记录了120分钟现行控制。试点期两套流程并行，总投入应再加现行控制工时，所以试点期间不一定节约。你可以估计获批替换后的稳态工时，但必须明确这是条件性预测；一次性开发与测试投入还应单独记录。

## 第三步：解释结果，形成下一轮试验

Study阶段需要说明为什么出现漏检与误报。T04说明两套结果之间缺少真正独立的输入验证；修复方案应强化来源校验或明确保留有效的独立复核。T08说明差异分类未正确应用获批规则，修复需要验证边界与累计影响，不能简单把小金额全部隐藏。

修复后的V2应冻结版本，重跑八个场景及所有受影响回归样本，并新增与缺陷根因有关的变体。还需验证角色能否理解提示、差异是否有负责人、错误是否真正关闭。仅在测试报告中将“失败”改为“通过”，没有相应运行证据，不构成修复。

本题没有提供V2结果，因此不能虚构V2已经通过，也不能因节约比例达标便推定可以上线。更合理的管理建议是：继续现行控制，在批准范围内修复并复测，保留候选方案的效率收益作为待验证预期。

## 第四步：安排授权、采用与回退

流程变化会改变谁需要判断、谁能够决定和团队实际承担的工作。机械比对减少后，人员可能需要更强的异常解释能力；绩效也应评价识别与关闭重要问题，避免只奖励处理量或低上报数量。培训要用具体失败情景演练，而不只是发送一份操作说明。

切换条件应包含版本、适用范围、培训、后备、数据访问和监测责任。回退安排则要说明谁能触发、恢复哪一版流程、如何取得原始资料，以及回退期间怎样保证交付。若发现重要漏检、证据不可访问或未经批准的规则变更，应按预设路径停止扩展并升级。

上线后仍需观察数据分布和业务变化。服务商字段变更、新账户、新币种或新产品可能使原试验结论失效。定期评估应将这些变更连回适用范围和测试清单，而不是把一次成功试点当作永久证明。

## 交付要求：写一份能用于决定的试点评估

评估意见应分别报告已观察事实、对稳态的估计、未覆盖情形和建议决定。列出工时口径、关键缺陷、根因、补充措施和复测要求，并标注决策权限。管理层需要据此判断是否继续投入，而不是只看到“效率提高”的百分比。

本项目允许不同实施建议，但不能接受三种结论：忽略关键漏检直接推广；把隔离样本全部通过说成覆盖所有产品；把候选流程的工时估计说成试点期间已经节约的实际总投入。

## 验收标准

- 将控制覆盖和效率作为不同验收维度
- 工时包含保留的复核，区分稳态与并行期
- 不忽略关键漏检，不虚构V2结果
- 建议包含授权、责任、回退和持续监测
